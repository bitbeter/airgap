# PRD ۵ — باز کردن فایل و کشیدن‌ورها کردن

## هدف
کاربر به‌جای کپی‌پیست، فایل متنی را مستقیماً در ورودی‌های diff و ویرایشگر Markdown باز کند. فایل فقط در مرورگر خوانده می‌شود.

## دامنه
1. دکمهٔ «باز کردن فایل» کنار هر ورودی (دو ورودی diff، ویرایشگر Markdown).
2. رها کردن فایل روی هر ورودی؛ در diff، رها کردن دو فایل هم‌زمان روی ناحیهٔ ورودی‌ها اولی را «اصلی» و دومی را «جدید» قرار دهد (ترتیب بر اساس نام، با پیام توضیحی).
3. پذیرش `.txt, .md, .markdown, .json, .csv, .log, .yaml, .yml, .xml, .html` و هر فایلی که `type` آن `text/*` است.
4. سقف حجم پیش‌فرض ۵ مگابایت با پیام فارسی.
5. تشخیص UTF-8 نامعتبر (`TextDecoder("utf-8", { fatal: true })`) و تلاش دوم با `windows-1256` برای فایل‌های قدیمی فارسی، با اعلام کدگذاری استفاده‌شده.
6. حفظ دقیق CRLF و BOM؛ BOM حذف و در پیام اعلام شود.

## خارج از دامنه
مقایسهٔ پوشه، فایل‌های باینری، DOCX/PDF.

## نیازمندی‌ها
- این منطق واقعاً مشترک است، پس در `src/components/file-open-button.tsx` و `src/lib/read-text-file.ts` قرار می‌گیرد (بدون import از features). فقط اجزایی که هر دو قابلیت لازم دارند مشترک شوند.
- در Markdown، باز کردن فایل روی متن غیرخالی تأیید بخواهد (`confirm` بومی یا دیالوگ ساده) چون پیش‌نویس جایگزین می‌شود.
- در diff، باز کردن فایل مثل ویرایش رفتار کند: worker فعلی بسته و نتیجه باطل شود.
- خطاهای خواندن صفحه را نشکنند.

## معیار پذیرش
- هیچ درخواست شبکه‌ای هنگام باز کردن فایل ثبت نمی‌شود.
- تست معماری مرز shared/feature را تأیید می‌کند.
- فایل فارسی ۱۲۵۶، UTF-8 با BOM، و CRLF درست خوانده می‌شوند.

## تست
`tests/read-text-file.test.mjs` در ریشهٔ `tests/` یا کنار ماژول مشترک طبق قرارداد فعلی؛ برای تست در Node منطق decode را در `.mjs` خالص با `.d.mts` بنویس.
