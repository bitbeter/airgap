## قالب هر PRD

هدف · مسئله · دامنه · خارج از دامنه · نیازمندی‌ها · رابط کاربری · داده و ذخیره‌سازی · پیاده‌سازی و فایل‌ها · معیار پذیرش · تست · ریسک‌ها · پرامپت پیشنهادی برای ایجنت.

## قواعد مشترک همهٔ PRDها

- رفتارهای حفاظت‌شدهٔ diff (`#/text-diff`، کلید `airgap:diff-history:v1`، سقف سه تاریخچه، دکمه‌های کپی، دقت مقایسهٔ کنارهم) نباید تغییر کنند مگر PRD صریحاً گفته باشد، آن هم به‌صورت انتخابی و با پیش‌فرض خاموش.
- هر ابزار جدید پوشهٔ خودش را در `src/features/<slug>/` دارد و فقط یک بار در `src/app/features.ts` ثبت می‌شود.
- منطق خالص در فایل‌های `.mjs` با `.d.mts` هم‌گام؛ تست‌ها کنار قابلیت در `tests/*.test.mjs`.
- کار سنگین در worker؛ worker هنگام لغو، تغییر ورودی و unmount بسته می‌شود و پاسخ‌های کهنه نادیده گرفته می‌شوند.
- ذخیره‌سازی فقط با کلید نسخه‌دار اختصاصی؛ خطای storage و clipboard صفحه را نمی‌شکند.
- اجرای `npm test`، `npm run build` و `npm run build:web` و گزارش هر بررسی مرورگری که انجام نشد.
