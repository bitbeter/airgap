# Markdown editor

Available at `#/markdown-editor`, with Persian labels and a responsive RTL layout: editor and live preview sit side by side on large screens and stack on smaller screens.

Uses the existing `react-markdown` and `remark-gfm` dependencies for headings, lists, links, tables, task lists, strikethrough, and code blocks, including Mermaid diagrams in fenced blocks tagged `mermaid`; common unlabelled Mermaid code blocks beginning with `graph`, `flowchart`, `sequenceDiagram`, and other Mermaid diagram keywords are detected automatically. Mermaid renders locally with a dark theme, strict security, bounded source size and edge count, cancellation on source changes, and a visible source fallback when rendering fails. Code blocks and inline code use isolated LTR direction. The textarea uses native `dir="auto"` and `unicode-bidi: plaintext` for per-paragraph direction. Each rendered paragraph, heading, list item, blockquote, and table cell uses independent native `dir="auto"` detection (first strong character, ignoring leading digits and punctuation). Lists reserve marker space on both sides for mixed-direction items. Tables retain the RTL page column order; cell text direction is independent, and explicit Markdown column alignment is preserved. Neutral-only blocks inherit the RTL page fallback. Raw HTML is skipped, unsafe URLs use the renderer's default filtering, and images render as text placeholders to avoid automatic external requests. Links open only on user interaction in a separate tab.

## Toolbar, shortcuts, and statistics

A toolbar above the editor inserts or toggles: headings 1–3, bold (`**`), italic (`_`), strikethrough, inline code, links, bullet/numbered/task lists, quotes, fenced code blocks, a 3-column table, a horizontal rule, and a sample Mermaid flowchart. It is one tab stop (`role="toolbar"`); arrow keys move in visual RTL order, Home/End jump to the ends. It wraps instead of hiding tools on narrow screens. Clicking a tool keeps the editor selection.

- Inline tools wrap the selection, trimming surrounding spaces outside the markers and wrapping each line separately; applying them again (with markers inside or just outside the selection) removes them. Without a selection they insert an empty pair, or remove an empty pair around the caret.
- Links use the selection as the label and select `https://` for replacement; a selected URL becomes the target. Without a selection, a placeholder label is selected.
- Line tools apply to every selected line (blank lines are skipped in multi-line selections), convert between list kinds and heading levels, and toggle off when every line already has that prefix. Numbered lists count each indentation level separately.
- Blocks go on their own lines, with blank lines around rules, tables, and Mermaid so a rule cannot turn the previous line into a heading. A selection is wrapped in a code block.

Shortcuts use physical key codes, so they also work with the Persian layout: ⌘ on Apple platforms and Ctrl elsewhere, plus B (bold), I (italic), K (link). Enter in a list item continues it (next number, empty task box); Enter on an empty item ends the list, adding a blank line after a filled line so following text is not joined to the list. Enter inside a fenced code block, before the marker, or with a selection keeps the default. Tab/Shift+Tab nest an item under its previous sibling or move it to its parent's level. Tab keeps its default focus movement whenever the caret is outside a list or nothing would change, so keyboard users are never trapped. IME composition is never intercepted.

Edits are computed by pure functions in `format.mjs` and applied as the smallest changed range with `document.execCommand("insertText")`, so browser undo/redo keeps working where supported; the resulting input event saves through the normal draft path. If native insertion is unavailable, the text is set directly and saved the same way, but that edit may not be undoable.

Below the editor, `stats.mjs` counts words with `Intl.Segmenter` (ZWNJ-joined Persian words count once; Markdown punctuation is ignored), characters as graphemes, lines, and reading time at 200 words per minute. Statistics follow the deferred preview value so typing stays responsive.

The latest draft is stored as an exact string in localStorage under `airgap:markdown-editor:draft:v1`. Every input change saves synchronously, without a debounce or waiting for preview rendering. Reloading or navigating back to the page restores that draft. This is a single latest-work entry, not a list of revisions. The clear button and deleting all input both remove only this key; whitespace-only input is preserved. Initial loading never overwrites storage. Storage access/quota failures keep the editor usable and show a Persian status message; unsuccessful saves leave the previous stored draft intact. No network calls, timers, or workers are introduced. React defers preview updates to prioritize typing; the preview updates without a submit action.

Format tests (`tests/format.test.mjs`) cover every toolbar action, toggling, multi-line selections, list continuation and ending, nesting, fenced code, and minimal edit ranges. Statistics tests cover ZWNJ, mixed text, graphemes, and reading time.

Validation: run `npm test`, `npm run build`, and `npm run build:web`. In a browser, check live edits and clearing, toolbar actions and keyboard navigation, shortcuts with English and Persian layouts, Enter/Tab in lists, undo after formatting, Persian/English text, GFM tables and code, narrow layouts, direct hash navigation, refresh, back/forward, and switching to the existing diff page. Feature tests render real Markdown to HTML and verify per-block direction attributes, GFM properties, code isolation, and safe rendering. Browser checks remain necessary to validate visual bidirectional layout. The repository architecture test checks import boundaries.

Draft tests cover exact-text recovery, replacement, explicit and manual clearing, unrelated keys, unavailable storage, and quota failures. Browser validation should include immediate reload after typing, navigation away/back, and reload after clearing.
